\chapter*{Scope and verification claim}

This project provides an auditable Lean core in which a pinned Wikifunctions implementation can
be stated and proved correct against a Mathlib specification.  It separates wire ingestion,
semantic values, schema validation, implementation elaboration, inner evaluation, public results,
language-specific execution, and mathematical meaning.

The target example is \wf{Z12427}/is prime.  Mathlib's \texttt{Nat.Prime} carries
\texttt{@[wikidata Q49008]}, and the bridge records the Q49008--\wf{Z12427} join.  The formal
target is the following kernel-checked Lean declaration:
\begin{verbatim}
@[simp]
theorem z12427_spec_eq_true_iff (value : Nat) :
    Z12427_spec value = true ↔ Nat.Prime value := by
  simp [Z12427_spec]
\end{verbatim}
This is a specification theorem, not a proof about the deployed foreign-language bodies.  A
separate, signature-linked conformance judgment states what such a proof must establish.

The strongest implementation theorem is for the transcribed \wf{Z13702} composition of
\wf{Z13701}/are coprime.  Its Z14 object is elaborated and evaluated, then proved equal to
\texttt{Nat.Coprime}, relative to explicit contracts for its strict leaf functions.

\chapter{Semantic values and wire forms}\label{ch:model}

\begin{definition}[Validated identifiers and keys]\label{def:identifiers}
  \lean{Wikifunctions.Model.ZID, Wikifunctions.Model.Key}\leanok
  ZIDs and keys carry proofs of their lexical grammar.  Keys include local keys, global keys, and
  the bare-ZID dynamic-key alternative admitted by the pinned \schema{Z7} schema.  Untrusted
  strings enter through partial parsers.
  \leansrc{Wikifunctions/Model/ZObject.lean}{48}
\end{definition}

\begin{definition}[Lossless raw syntax]\label{def:raw}
  \lean{Wikifunctions.Model.Raw}\leanok
  Raw syntax preserves strings, number spelling, booleans, null, arrays, object order, and
  duplicate keys.  It is the untrusted JSON-shaped boundary and the payload language of quotes.
  \leansrc{Wikifunctions/Model/ZObject.lean}{152}
\end{definition}

\begin{definition}[Semantic ZObject syntax]\label{def:zobject}
  \uses{def:identifiers, def:raw}
  \lean{Wikifunctions.Model.ZObject}\leanok
  Strings, references, ordinary typed objects, typed lists, and quotes are distinct constructors.
  A quote retains raw syntax rather than requiring its payload to be a valid semantic ZObject.
  \leansrc{Wikifunctions/Model/ZObject.lean}{167}
\end{definition}

\begin{definition}[Structural validity and quote opacity]\label{def:structural}
  \uses{def:zobject}
  \lean{Wikifunctions.Model.ZObject.StructurallyValid,
    Wikifunctions.Model.ZObject.structurallyValid_quote}\leanok
  Ordinary objects require unique keys, no second data-level \texttt{Z1K1}, and recursively valid
  semantic children.  Z99 is a hard validation boundary: its raw payload is not traversed.
  \leansrc{Wikifunctions/Model/ZObject.lean}{214}
\end{definition}

\begin{definition}[Canonical and normal rendering]\label{def:serialization}
  \uses{def:zobject}
  \lean{Wikifunctions.Model.Canonical, Wikifunctions.Model.canonicalize,
    Wikifunctions.Model.ZObject.toNormal}\leanok
  Semantic canonical form retains the string/reference distinction.  Normal form expands
  terminals and \wf{Z881} lists.  Both renderers reproduce a quoted raw payload exactly.
  \leansrc{Wikifunctions/Model/Serialization.lean}{18}
\end{definition}

\begin{lemma}[Semantic conversion inverses]\label{lem:semantic-inverses}
  \uses{def:serialization}
  \lean{Wikifunctions.Model.normalize_canonicalize,
    Wikifunctions.Model.canonicalize_normalize}\leanok
  Canonicalization and normalization are structural inverses.  A ZID-shaped Z6 string is never
  reinterpreted as a Z9 reference inside the semantic layer.
  \leansrc{Wikifunctions/Model/Serialization.lean}{68}
\end{lemma}

\begin{definition}[Exact renderer-image decoding]\label{def:wire-safe}
  \uses{def:structural, def:serialization}
  \lean{Wikifunctions.Model.decodeNormal, Wikifunctions.Model.decodeCanonical,
    Wikifunctions.Model.WireSafe}\leanok
  These strict decoders characterize the exact field order and shapes emitted by the renderers.
  \texttt{WireSafe} states the constructor-disjointness needed because the permissive semantic
  inductive can express ordinary objects that collide with reserved wire encodings.
  \leansrc{Wikifunctions/Model/Decode.lean}{205}
\end{definition}

\begin{lemma}[Renderer round trips]\label{lem:wire-roundtrip}
  \uses{def:wire-safe}
  \lean{Wikifunctions.Model.decodeNormal_toNormal_of_wireSafe,
    Wikifunctions.Model.decodeCanonical_canonicalize_toRaw_of_wireSafe}\leanok
  Both exact decoders are proved left inverses on their explicit serialization domain.
  \leansrc{Wikifunctions/Model/Decode.lean}{610}
\end{lemma}

\begin{definition}[Order-independent JSON ingestion]\label{def:ingest}
  \uses{def:raw, def:structural}
  \lean{Wikifunctions.Model.ingestNormal, Wikifunctions.Model.ingestCanonical,
    Wikifunctions.Model.sortRawFields}\leanok
  External ingestion rejects duplicate keys, looks members up by name, and sorts ordinary data
  fields deterministically.  Reordered \texttt{Z1K1}, terminal, and \wf{Z881} fields are accepted;
  a recognized Z99 payload is returned without descent.
  \leansrc{Wikifunctions/Model/Ingest.lean}{45}
\end{definition}

\begin{lemma}[Malformed quotes are preserved]\label{lem:quote-preserved}
  \uses{def:ingest}
  \lean{Wikifunctions.Model.ingestNormal_malformed_quote_preserved,
    Wikifunctions.Model.ingestCanonical_malformed_quote_preserved,
    Wikifunctions.Model.ingestNormal_reordered_typed_list,
    Wikifunctions.Model.ingestNormal_literal_identity_list}\leanok
  Kernel-checked examples preserve a raw object containing duplicate invalid keys, a noncanonical
  number, and null inside Z99, while also accepting reordered typed lists and the pinned recursive
  literal Z4/Z8 list-identity forms.
  \leansrc{Wikifunctions/Model/Ingest.lean}{230}
\end{lemma}

  forms are rejected and nested callees consume schema fuel.
  \leansrc{Wikifunctions/Model/Schema.lean}{218}
\end{definition}

\begin{definition}[Pinned core schemas]\label{def:core-schemas}
  \uses{def:resolver-schema}
  \lean{Wikifunctions.Model.Schema.Core.z7LiteralSchema,
    Wikifunctions.Model.Schema.Core.z14LiteralSchema,

\chapter{Composition semantics}\label{ch:semantics}

\begin{definition}[Z7/Z18 expression language]\label{def:expr}
  \uses{def:zobject}
  \lean{Wikifunctions.Semantics.Expr}\leanok
  Expressions have literals, keyed Z18 argument references, raw opaque quotes, and Z7 calls whose
  callee is itself an expression.  IDs remain open data rather than a closed Lean enumeration.
  \leansrc{Wikifunctions/Semantics/Eval.lean}{36}
\end{definition}

\begin{definition}[Expression decoding]\label{def:expr-decode}
  \uses{def:expr, def:resolver-schema}
  \lean{Wikifunctions.Semantics.decode,
    Wikifunctions.Semantics.decode_z18_argument_of_parse,
    Wikifunctions.Semantics.decode_duplicate_z7_callee_rejected}\leanok
  The fuelled semantic boundary decodes expression-valued callees and arguments, validates global
  Z18 keys, keeps quotes opaque, and rejects malformed reserved forms.
  \leansrc{Wikifunctions/Semantics/Decode.lean}{60}
\end{definition}

\begin{definition}[Typed signatures and registry]\label{def:registry}
  \uses{def:expr, def:schema-ir}
  \lean{Wikifunctions.Semantics.FunctionSignature,
    Wikifunctions.Semantics.FunctionSignature.acceptsArguments_pair_swap,

  A Z8 projection stores ordered Z17-style key/schema declarations and an output schema.

\begin{definition}[Persistent values and reference resolution]\label{def:references}

\chapter*{Open proof obligations}

Green nodes state the implemented core precisely.  The following production-wide claims remain
outside it:
\begin{itemize}
  \item conformance of Z12427's deployed Python and JavaScript bodies;
  \item conformance of the deployed strict implementations used as leaf contracts;
  \item a complete live Z4/Z8/Z17 registry and type-directed resolution inside arbitrary object
        fields, including the special Z2-as-argument rule;
  \item runtime-wide schema enforcement for arbitrary nested composition/lazy calls (strict and
        foreign boundaries validate schemas; typed contracts prove their own encoded domain);
  \item literal/transient Z8 identities and literal Z61 languages beyond the pre-resolved
        persistent-ID elaboration subset;
  \item a concrete revision-pinned metadata map containing typed Z5 errors; and
  \item equivalence between this deterministic strategy and a selected production evaluation,
        Python, or JavaScript semantics.
\end{itemize}
These are explicit interfaces or premises, not hidden assumptions of the green theorems.
